# 制作 skill 与工具接口验证

本轮将制作调度交给 Codex skill，并复用现有 Python 执行器。没有新增模型、依赖、下载或 GPU 生成任务，也没有修改既有角色的素材和绑定。

## 实现

- 新增 `l2d inspect`：离线读取图片、部件和参数，重新核验阶段文件哈希，并返回素材/模型包结构检查。
- 新增 `l2d render`：接收参数与可选画布区域，使用临时工作区渲染，拒绝未知参数、越界值及无效区域。
- 新增 `l2d preview-video`：调用既有参数动画实现；新增 `l2d schema` 暴露实际输入类型。
- 新增 `l2d repair`：草稿创建、更新、执行、证据、agent 检查、应用和丢弃。CLI 直接接收本地图片，网页上传接口保持原契约。
- Agent 检查绑定草稿版本、候选完成凭据和图片哈希；过期证据与失败/不确定检查不能正常应用。保留既有的明确人工确认机制，agent 检查不标记用户接受。
- 移除 `Pipeline.run` 内隐式的缺层规划补画。缺层时保存已有素材并返回 `paused`，通过显式修正步骤继续。
- 制作 skill 位于 `skills/live2d-production/`，已链接到本机 `/home/kurage/.codex/skills/live2d-production`。包含工具合同、质量检查、修复路径与迭代预算。

## 后续调整：本地模型仅用于全本地任务

根据用户补充要求，默认 `execution.mode` 改为 `agent`，省略该字段也使用 agent。Codex 负责规划与视觉判断，生图/编辑优先调用 agent 自带的图像工具，只有用户明确指定时才使用其他工具或服务。只有明确要求全本地运行时，才给该任务单独配置 `mode = "local"`。

- 本地规划、VLM 和容器/原生推理入口均检查模式；覆盖 ComfyUI、See-through、SAM2、LaMa 等调用。CPU 的 PSD 处理、绑定、渲染、像素检查和导出继续可用。
- 生成管线在改写版本状态或阶段产物前，拒绝默认模式下需要本地模型的操作。
- 当前没有云端自动拆层适配器，agent 模式需外部提供分层 PSD 或已处理的部件，缺失能力时不自动降级到本地模型。
- 增加 8 项策略回归；完整检查 **154 passed**。原本测试本地后端协议的用例改用明确启用 local 的配置，均未实际启动模型。Skill 与 README 已同步此策略。
